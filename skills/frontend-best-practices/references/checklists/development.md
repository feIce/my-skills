# 开发检查清单

## 概述

本文档提供前端开发过程中的检查清单，确保代码质量和一致性。

---

## 一、代码规范

### TypeScript

- [ ] 使用 TypeScript 严格模式
- [ ] 无 any 类型（除非绝对必要）
- [ ] 所有函数有返回类型注解
- [ ] Props 有完整的接口定义
- [ ] 使用 interface 而非 type（对象结构）
- [ ] 使用 type 定义联合类型、交叉类型
- [ ] 泛型有适当的约束
- [ ] 类型守卫用于运行时验证

### 命名规范

- [ ] 变量和函数使用 camelCase
- [ ] 组件和类使用 PascalCase
- [ ] 常量使用 UPPER_SNAKE_CASE
- [ ] 文件命名符合规范（组件：PascalCase.tsx，工具：kebab-case.ts）

### 代码结构

- [ ] 函数保持简短（建议不超过 50 行）
- [ ] 组件保持单一职责
- [ ] 导入顺序正确（React → 外部库 → 内部模块 → 类型 → 样式 → 常量）
- [ ] 有适当的注释（JSDoc）和代码注释

---

## 二、React 组件

### 组件设计

- [ ] 使用函数组件而非类组件
- [ ] Props 接口定义完整
- [ ] 使用 children 而非 content prop
- [ ] 组件有明确的职责
- [ ] 避免组件过于庞大（超过 300 行考虑拆分）

### Hooks 使用

- [ ] useEffect 依赖数组正确
- [ ] 清理函数完整（定时器、订阅等）
- [ ] 避免在 useEffect 中使用 async（使用 IIFE 或分离函数）
- [ ] useCallback 用于传递给子组件的回调
- [ ] useMemo 用于复杂计算

### 状态管理

- [ ] 状态放在合适的层级
- [ ] 避免不必要的状态
- [ ] 使用 useReducer 处理复杂状态
- [ ] Context 不过度嵌套
- [ ] 状态更新使用函数形式（prev =>）
